# sibylsign Style Spec

This is the contract every icon must obey. Sub-agents author icons to this spec; humans review only when validation fails.

## Canvas

- **Sizes**: 32×32 px and 64×64 px. Every concept emits both sizes.
- **Padding**: at least 2 px of empty space on every edge so the icon never touches the canvas border.
- **ViewBox**: `0 0 N N` matching the declared size.
- **Background**: transparent. Never fill the canvas with a rectangle.

## Color

- **Single hue**: `#000000` (solid black) for every visible mark.
- **No transparency, no grayscale, no gradients.** Strokes and fills are solid black.
- **Cutouts use evenodd**: when a filled shape must contain a "hole" (e.g. a checkmark inside a checkbox), use a single `<path>` with `fill-rule="evenodd"` rather than stacking a black shape on top of a white shape.

## Geometry

Allowed primitives (composed freely, no restriction on count):
- `<rect>` and `<rect rx ry>` (square and rounded rectangle)
- `<circle>`, `<ellipse>`
- `<line>`
- `<polyline>`, `<polygon>`
- `<path>` with explicit `d` (especially for cutouts)
- Plain SVG `<text>` is **not** allowed. Glyphs must be drawn from primitives, not rendered text.

Stroke widths:
- 32 px canvas: 1 px to 2.5 px
- 64 px canvas: 2 px to 5 px
- Keep stroke widths consistent across the icon.

## Style targets per archetype (illustrative)

- **Button**: rounded rect (rx ≈ 4 in 32) with an inner label bar cutout for filled, or a centred label stroke for outline.
- **Checkbox**: square with a check cutout for selected state; outline square with an inner dash for intermediate.
- **Radio**: circle with a smaller filled inner circle for selected state.
- **Toggle / Switch**: pill-shaped track with a knob dot; for `on` state, use evenodd cutout instead of overlapping shapes.
- **Input**: bordered rectangle with a placeholder dash, an inner cursor stroke, or a label stroke.
- **Alert / Banner**: rounded rectangle with a left accent stripe and a right-side content area.
- **Modal / Card / Panel**: bordered rectangle with internal title bar and body lines.
- **Progress bar**: bordered track with a filled portion; for vertical, swap x/y axes.
- **Spinner**: 8 dots arranged on a circle, one segment emphasized.
- **Bell / Notification**: dome/trapezoid + clapper dot + optional badge dot.
- **Icon-Button, Search, Filter, Sort**: recognizable glyphs (magnifier with handle, funnel with stem, three stacked lines for sort).

## Visual recognition

An icon is considered good if a human glancing at the PNG can identify its concept within ~2 seconds. The validator catches structural problems; a separate visual review is performed by the dispatching agent (which renders the PNG to base64 and self-checks) plus, on the first batch per subcategory, by the user.

## File layout

- Source: `svg/<size>/<category>/<name>.svg`
- Rasterized: `png/<size>/<category>/<name>.png` (derived; generated by the existing pipeline)
- Names: kebab-case; for ui-kit a short name without the Cartesian modifier is preferred, e.g. `button.svg`, `button-filled.svg`.

## Failure mode

If an agent produces an icon that fails validation or is not visually recognizable, retry up to 2 times with concrete feedback. After 2 retries, leave the icon in `deferred/<subcategory>/<name>.svg` with a `deferred-` prefix in the descriptive name and continue.
